# 给提取指令加一条「对话推翻已存条目就改掉」的规则：实测没有差别，不加

> 状态:rejected · 提出 2026-11-18（读 Anthropic《The components of agent memory》，Lance Martin，2026-11-06：离线复盘对着对话记录改掉记错的笔记。对照本仓，整理读不到对话，提取指令的任务又写成「有没有值得留的」，由此推断「后台没有一步会去纠错」）· 用户同意「改完用真模型测一下再定」· 2026-11-18 实测后撤回：现行指令已经会改，加不加这条没有差别

**给谁看**：想改提取缺省指令的人；想知道一条记错的记忆什么时候会被改掉的人。

## 提的是什么

在 [`defaultExtractPrompt`](../../../packages/core/src/memory/extract.ts#symbol=defaultExtractPrompt) 里把任务从「有没有值得留的」扩成两件（另问「上文有没有说明已存的某条错了」），并在对每个模块都成立的规则里加第三条：对话推翻了已存条目——用户亲口说的不一样，或照着它做失败了、换一种做法才对——就改写或删掉；只此一次的例外不算。

## 实测

`deepseek-flash`，单层、内建三个模块。前台走脚本（含工具调用与结果），只有提取走真模型；每格 5 次，全部在轮数上限内跑完。

六种该改的情形：

| 情形 | 现行指令改对 | 加了规则改对 |
|---|---|---|
| 记错的测试命令在 indexed 笔记里；照做失败、换了做法才成，助手在回答里说明了原因 | 5/5 | 5/5 |
| 同上，但助手的回答没提，反证只在工具结果里 | 5/5 | 5/5 |
| 同一条错的在常驻模块里 | 5/5 | 5/5 |
| 错的细节在笔记正文里，描述行看不出来 | 5/5 | 5/5 |
| 用户顺口说地址变了（同一条里另一半规矩仍成立，两种写法都保住了它） | 5/5 | 5/5 |
| 用户顺口说那个环境整个下线了 | 5/5 | 5/5 |

六种情形的平均模型调用：现行 3.2，加了规则 3.2。

两种不该动的情形：

- **只此一次的例外**（已存「测试一律用 bun」，用户说「就这一次用 npm test」）：两种写法都没有把已存的规矩改反（0/5、0/5）。都倾向把这次例外记下来：现行 5/5（4 次另起一条或并进别的笔记，1 次补在原条目后面），加了规则 4/5（3 次补在原条目后面，1 次另起一条），另 1 次什么都没写。
- **没有可记、也没有矛盾的对话**：现行 1/5 多写了一条（仓库里有个脚本），加了规则 2/5。原有条目没有被删，原有内容也没有被改掉。

样本小，只说明方向：两种写法的差别在噪声以内。

## 为什么现行写法已经会改

提取从主对话分叉，带着主循环的 system：规则段写着发现记错了就删、与用户在这次对话里说的冲突就照对话改（[`renderMemoryRules`](../../../packages/core/src/memory/compose.ts#symbol=renderMemoryRules)）。提取指令又要求同一条事实只放一处、已经有了就更新那一条。两处都在提取眼前；哪一处起主要作用没有拆开测。

## 决定

不加。多一条没有带来差别的规则，只多了字数。

## 这次实测没有覆盖的

- **对话里从没出现反证的错条目**：没有任何一步会去查。整理读不到对话记录（[删掉整理的水位门](../implemented/2026-11-12-dream-watermark-removed.md) 里记为另议），这次不动。
- 更强的模型、产品自定义的模块与指令没有测。
- 评测脚本不入库（与此前几次同样处理）。
