# 记忆提取从主对话分叉、攒满三轮才跑、退出前补一次、游标落盘

> 状态:implemented · 提出 2026-11-03（三方缓存对比：echo 未命中是 pi / dsh 的两倍多，约四成来自记忆提取；同时复现「最后一轮答完就退出、那一轮永远不被提取」）· 拍板 2026-11-03（用户：「这几个问题都要解决，多次记忆提取的问题也要解决」——即 [降频](2026-10-30-memory-extraction-gate.md) 那份两步方案的第 2 步，加降频与退出补跑）· 落地 `packages/core/src/memory/extract.ts` / `channel.ts` / `agent.ts` / `create-echo.ts` / `session/types.ts` / `session/service.ts`，判据 `packages/core/test/memory-extract.test.ts`、`packages/core/test/create-echo.test.ts` · 修改 [降频](2026-10-30-memory-extraction-gate.md) 的第 2、3 条与 Non-Goals

**给谁看**：改记忆提取的触发、输入、成本或收摊顺序的人。假设已知 [降频](2026-10-30-memory-extraction-gate.md)（门槛 + 游标）与 [记忆设计](../../design/memory.md) §5。

**一句话**：提取不再另起一套 prompt、把对话拍平重发，而是接在主对话后面跑（前缀与主循环最后一次请求逐字相同，厂商缓存直接接着用）；攒满三轮用户输入才跑；退出前不论攒了几轮都补一次；复盘到哪落盘进会话，没提取的那截跨重启接着攒。

## 现状（拍板前）

- **贵**：提取是一套没有 system 的独立 prompt，游标之后的对话拍平成文本塞进去，主循环的前缀缓存一分都吃不到。2026-11-03 三方对比（同一段 5 句脚本、同一模型 `deepseek-flash`）：echo 主循环的复用与 pi、dsh 持平，但总未命中 33.0k，pi 14.3k、dsh 13.6k；echo 多出来的约四成来自提取，其中读完一个 35KB 文件之后那次提取把文件内容原价重发了约 1 万 token。
- **频**：8 个词的门槛只挡得住致谢、确认，正常提问几乎句句过线——那段 5 句脚本触发了 4 次提取、8 次请求。
- **丢**：`stop()` 一开始就改相位、关业务写入，接着 `settleDream()` 把排着的提取丢掉、在跑的中止；续会话又把游标直接设到末尾。于是「最后一句答完就退出」的那一轮永远不会被提取。确定性复现：同一句 11 个词的话，答完立刻关 stdin 发出 0 次提取请求，多留 15 秒发出 1 次。这与 [降频](2026-10-30-memory-extraction-gate.md) 否决空闲触发时给的理由（「交互形态退出前的最后一段会丢」）正好相反。

## 决定

1. **从主对话分叉**（`Agent.runExtract`）：system = 主循环每个 run 装配的那一份（`assemblePrompt`，记忆段是冻结的那一版）；菜单 = 主循环此刻的菜单（`visibleTools`，reply 收尾时定格）；消息 = 主循环的 working context（含最后那条回答），末尾接一条提取指令。指令只说清看哪一段——最后几条、从哪句用户原话开始（两样都给：provider 换算消息时会拆合，单给条数模型数不准）——外加层、模块与「此刻存着什么」（system 里的记忆段是会话开头那一版，之后写的看不到）。
2. **菜单照摆，只放行记忆工具**：记忆工具换成这次提取的实例（同一个工厂、同一份 schema，事实挂在提取的 run 上）；其余换成同名同 schema 的替身（`refusedDuringExtract`），一点名就在修参那一步拒掉——早于 preToolUse 与权限，后台复盘不会去问人、不惊动 hook。循环按冻结菜单里的实例执行，只在 `resolveTool` 上拦是挡不住的。主菜单上没有记忆工具时补在末尾（前缀在工具那段断开，但照样能写）。
3. **攒满三轮才跑**：`DEFAULT_EXTRACT_EVERY_TURNS = 3`，一轮 = 一条 `human` 用户消息（`humanTurns`；steer 是同一轮里的插话）。与 8 词门槛同时满足才跑，任一没过就攒着、游标不动。数值参照物缺省是 1（远端可调），这里先取 3，实测后再调。
4. **退出前补一次**（`Agent.drainExtract`）：不看攒了几轮（仍过 8 词门槛），等它跑完，最多 `DEFAULT_EXTRACT_DRAIN_MS = 15_000`，到点照常收摊（提取被中止、游标不动）。两个调用点：`echo.stop()` **在卸 Extension 之前**（记忆模块、记忆工具、prompt 段都是 builtin 挂的，卸完就没得提取、前缀也对不上）；`Agent.doStop()` **在改相位之前**再调一次，给低层用法兜底，前面补过就空转。丢锁不补（一个字都不许再写）；handoff 让位不补（有人在等这把锁；被叫醒的会话处理的是 inbox 消息，本来也过不了门槛）。
5. **重叠保护不再推游标**：前台这条 reply 自己写过记忆，这条 reply 不单独起提取，但游标不动。攒满三轮之后再推游标，会把前面攒着、前台没看过的几轮一起丢掉；分叉出来的提取在上文里看得见前台那次写入，指令里也有「此刻存着什么」，不靠跳过来防重复。

同日第二批（用户转述的反馈：「读取记忆误判为写入，待提取内容不能跨重启累计，提取和整理成本优化」）：

6. **读不算写**：重叠保护只认前台那把 memory 工具一次**非 view** 的调用成功（`Agent` 构造期包在那把工具上，判法与 `runExtract` 数写入条数同一条）。此前看的是「memory 工具成功结束」事件，前台 view 一下记忆，那一轮就被当成写过、提取被跳过。
7. **游标落盘**：提取正常跑完，会话里记一条 `memory_reviewed { at, through }`（`SessionEntry` 新的一种，`through` 是**落盘消息**的下标）；续会话取最后一条（一条都没有 = 0，`SessionData.memoryReviewedThrough`）。`/clear` 只清内存、不写会话，续会话时 reset 之前的消息会回来，所以 Agent 记一个偏移，落盘下标 = 内存下标 + 偏移。**改的是持久化格式与公共类型**（`SessionEntry` / `SessionData` 从包入口导出）：只追加；旧会话没有这种 entry，续上后第一次提取从头看起（分叉跑，成本是一次普通请求）；旧版本读新会话会因为不认识的 kind 判红（pre-release，不留兼容）。格式改动 2026-11-03 用户同意（「都修复掉」）。
8. **Dream 不带每轮注入**：激活 skill 正文、任务清单是前台这场对话的，整理只看已有记忆——此前 `turnInjections: "inherit"`，每轮多发一段。
9. **Dream 的 prompt 要求批量、只回一行**（`defaultDreamPrompt`）：实测（真实 API，同一份 12 条笔记、两组重复加一条被推翻的旧偏好）模型自己会把 view 并起来，改写却是一条一轮——16 次请求里 11 次只调一次工具；收尾总结占全部输出的 17%，而整理的事件不外发、没人读。加两句之后：请求 16 → 5、输入 58.5k → 14.4k、输出 2.9k → 1.7k、单次 $0.0050 → $0.0028。合并质量两次都对（重复并成一条、被推翻的那条注明了取代关系）；有一条「模型名」的笔记改前留着、改后删了——笔记模块的判据本就说「仓库里写着的不记」，各一次样本分不出是不是这两句引起的。不把「当前内容直接放进 prompt」：view 本来就并发，省不了几次请求。
10. **Dream 轮数用完按「做了一部分」记**（用户：「修复」）：`markDreamPartial()`——放锁、记时间、计数不清，报 `dream_partial`；下次按正常间隔接着做。此前按失败记：不记时间、锁 1 小时后过期、门还满着，层大到一次做不完时每小时整套重跑。provider 出错等其余失败照旧（锁过期后重来）。

11. **水位门要有新写入才再开**（实现第 10 条时发现、先登记，用户「都修复掉」后落地）：水位门单独成立、不看间隔，一次整理结束（跑完或做了一部分）而占用仍在线上时——内容都值得留、合并不动它——此前**每次回到 idle 都会再整理一次**。`DreamState` 加 `writesAtLastPass`（整理结束那一刻的 `writes`：跑完时 0，做了一部分时是当时的值），水位门要 `writes` 涨过它（或从没整理过）才开。登记时写的「`writes > 0`」不够：第 10 条做了一部分时计数不清，`writes > 0` 恒真。状态文件是记忆层内部格式（不导出），旧文件没有这个字段按 0 读。

## Non-Goals

- 不做空闲补跑、「先问一句」：退出补跑已经兜住「没攒满就结束」，空闲补跑只多一个计时器。
- ~~游标不落盘~~（第 7 条改了：被杀、补跑没跑完的那截，续会话后接着攒）。
- 不改提取的模型、轮数上限（5）。提取仍不进 admission、走自己的通道。
- 门槛、轮数、补跑上限都不做成产品配置。
- 不改 Dream。
