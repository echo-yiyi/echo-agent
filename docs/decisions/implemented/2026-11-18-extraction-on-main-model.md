# 提取沿用主循环的模型，不另配便宜档

> 状态:implemented · 提出 2026-11-18（[记忆的产生](2026-09-07-memory-extraction.md) 写着提取「模型走产品配的便宜档」，一直没实现，设计文档把它列为决策与实现的差距）· 拍板 2026-11-18（用户：「两条都做」）· 实现不变——提取一直用主循环的模型；改的是决策与文档，判据见验收 · 取代 [记忆的产生](2026-09-07-memory-extraction.md)「隔离子 agent，全套记忆工具」一节里的「模型走产品配的便宜档」

**给谁看**：想给记忆提取省钱的人；改提取子循环装配的人。

## 现状

2026-09-07 定的是提取走便宜档，理由是「没人看着的后台活，成本必须有硬上界」。这一档从来没做：[`Agent.runExtract`](../../../packages/core/src/agent.ts#symbol=Agent.runExtract) 用的是排它的那次 run 的模型绑定。

那之后变了两件事：

1. **提取改成从主对话分叉**（[从主对话分叉](2026-11-03-memory-extraction-fork.md)）：system、工具菜单与消息前缀同主循环最后一次请求逐字相同，为的是接上厂商的前缀缓存。前缀缓存缓存的是某个模型对这段前缀的计算结果，换一个模型就接不上，这段前缀要按原价重发。**这一条是推断，没有在厂商接口上实测。**
2. **成本另有上界**：轮数上限（产品可配）、攒满几轮才跑、只看游标之后的新内容（[记忆提取降频](2026-10-30-memory-extraction-gate.md)、[记忆的可调取值](2026-11-12-memory-tuning-config.md)）。

## 参照

Anthropic《The components of agent memory》（Lance Martin，2026-11-06）在同一组任务上比较了几代模型有没有记忆的得分：强的一档从 0.564 到 0.828，弱的一档只从 0.330 到 0.364，后者记下的是一堆没验证过的猜测；另一组实验里弱模型写了 413 个文件、强模型只写了 10 个，走得更远的是后者。

判断什么值得记、哪条已经记错了，是提取里最吃模型能力的一步。交给便宜档，省的是调用费，赔的是记忆质量——记错的常驻条目会被带进之后的每一个会话。

以上数字出自该文，本仓没有复测；它是参照，不是本仓的设计依据。

## 决定

提取沿用主循环的模型。不做「便宜档」，也不为它开配置项。

## Non-Goals

- 不给 `memory.extract` 加模型字段。产品真要换模型，带着自己的数据来再议。
- 不动整理（Dream）用哪个模型：它同样用排它的那次 run 的模型绑定，本记录不涉及。
- 不实测换模型之后的前缀缓存命中率：不做这一档，就不需要这组数。

## 验收

- [提取用的就是主循环的模型](../../../packages/core/test/memory-extract.test.ts#test=提取用的就是主循环的模型不另配一档2026-11-18换了模型厂商的前缀缓存接不上判断记什么哪条记错了也正是最吃模型能力的一步)：提取子循环的每一次模型调用，拿到的模型与前台最后一次请求相同。把 `runExtract` 交给子循环的模型换成另一个，这条是红的。
- [持久记忆](../../design/memory.md) §5 写明不另配便宜档，§8 不再把模型档列为决策与实现的差距。
