# `echo-coding` 的 web_fetch 缺省不取内网地址，重定向逐跳重查

> 状态:implemented · 提出 2026-11-03（echo-coding 工具线排查）· 拍板 2026-11-03（用户：「全部按推荐修」）· 实现 2026-11-03 · 来源 [`isPrivateAddress`](../../../packages/coding/src/tools/web.ts#symbol=isPrivateAddress)，判据 [地址段](../../../packages/coding/test/web.test.ts#test=isprivateaddressloopback私网链路本地含云元数据cgnat未指定ipv6-同类与-ipv4-映射一律算内网边界外的照常)、[缺省拒绝](../../../packages/coding/test/web.test.ts#test=webfetch-缺省拒绝内网地址本机服务一次请求都收不到报错说明这是安全限制)、[解析结果任一落段](../../../packages/coding/test/web.test.ts#test=webfetch-主机名解析出的地址任一落在内网段就拒)、[重定向逐跳](../../../packages/coding/test/web.test.ts#test=webfetch-重定向逐跳跟随每跳重查跳到内网就拒不发出那一跳跳太多次报错正常跳转照常并注明)

## 现状(拍板前)

`web_fetch` 对 URL 只查协议是 http(s)，然后 `fetch(..., { redirect: "follow" })`。复现：本机起一个服务，`web_fetch http://127.0.0.1:<port>/admin` 照取不误、正文回进对话。web_fetch 不做出网确认（2026-09-03 拍板），取回的网页是不可信内容：一页里的一句注入就能让模型去取 `http://169.254.169.254/` 的云实例凭据、本机开发服务的管理口、内网服务，再把结果带进上下文；公网页面回一个 302 指到内网，连 URL 都不用模型自己写。

## 选项

- **A. 不拦**：出网不确认是拍过的，内网也一样放行。代价是上面那条路一直开着。
- **B. 缺省拒绝非公网地址，重定向改成手动逐跳跟、每跳重查**。主机名先解析，任一结果落在拦截段就拒。要取本机服务（自己的 dev server）走 bash（`curl`）——bash 由权限策略管。
- **C. B 再加连接层固定地址**（查过的地址就是连接的地址，堵 DNS rebinding）。`fetch` 不让指定连哪个地址；要自己实现 HTTP/TLS 连接或换依赖，超出这次范围。

参考：opencode 的 webfetch 同样手动跟重定向（上限 10 跳）、每跳过一遍它的权限规则，但不按地址段拦。codex 的网络代理有同类判据（`codex-rs/network-proxy/src/policy.rs` 的 `is_non_public_ip`）：本条的段它都拦，另外还拦组播、广播、文档用的 TEST-NET、`198.18/15`、`240/4`；IPv6 先 `to_ipv4()` 再判，与本条对 IPv4 映射的处理相同。

## 决定

**B**（2026-11-03 用户拍板）。

- **拦截段**（`isPrivateAddress`）：IPv4 的 `0.0.0.0/8`（未指定）、`10/8`、`127/8`、`169.254/16`（链路本地，含云元数据 `169.254.169.254`）、`172.16/12`、`192.168/16`、`100.64/10`（CGNAT）；IPv6 的 `::`、`::1`、`fc00::/7`、`fe80::/10`，以及 IPv4 映射 `::ffff:a.b.c.d` 与旧的 IPv4 兼容写法 `::a.b.c.d` 按里面那个 IPv4 判（不判就是绕过：`http://[::ffff:127.0.0.1]/` 实测能连到本机服务）。认不出的地址按内网处理。
- **主机名**：每跳发出之前解析（IP 字面量原样，其余系统 DNS、取全部地址），**任一**结果落段就拒。
- **重定向**：`redirect: "manual"`，最多 10 跳（与 opencode 同数），每跳先解析新地址再发；跳到非 http(s) 是 error。
- **报错**：写明哪个主机解析到哪个地址、是重定向带过去的就说从哪跳来，并说明「这是安全限制，不是网络错误」。不在报错里教模型改用 bash 去取——那正是要拦的那条路，用户要取本机服务时自己会让它用 bash。
- **没有给产品或嵌入方的放行开关**。`WebDeps.resolveHost` 只是测试接缝：换的是「查什么」（本机假服务在 127.0.0.1，测试把它解析成公网地址才发得出去），判据本身不放开。

**已知缺口**：DNS rebinding——检查时那次解析与 `fetch` 自己那次之间，恶意 DNS 可以换答案。要堵得走选项 C。codex 多拦的那几类（组播、广播、TEST-NET、`198.18/15`、`240/4`）不在本条：它们上面没有能被取到的服务，要补是加几行段判据的事。

## 验收

上面四条判据：拦截段内外的边界值各一组；缺省装出来的 web_fetch 对 127.0.0.1、localhost、`[::1]`、169.254.169.254、10.x、`[::ffff:127.0.0.1]` 一律 error 且本机假服务一次请求都没收到；解析结果混着公网与私网地址也拒；公网页 302 到 localhost 时只有第一跳发出去、报错提到重定向，循环重定向报 Too many redirects，正常重定向照常并注明最终 URL。
