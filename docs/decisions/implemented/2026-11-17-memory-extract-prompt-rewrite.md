# 提取指令的缺省写法重写：两轮做完、常驻带上限、一条事实一个地方

> 状态:implemented · 提出 2026-11-17（用户：「如果能拿到 claude 这部分提示词换成我们的默认提示词就最好了，感觉我们现在的提示词不是很好」）· 落地 `packages/core/src/memory/extract.ts` 的 `defaultExtractPrompt`，判据见验收 · 承接 [提取 / 整理指令交给产品](2026-11-17-memory-prompts-and-gates.md)（那份留了「缺省措辞这次不改」）· 整理指令的缺省写法**这次不换**，原因与数据见下

**给谁看**：改提取指令缺省写法的人，以及想知道缺省为什么这样写、要不要自己换的产品。

## 怎么来的

参照物（Claude Code）的提示词是专有文本，**不抄措辞与节名**（用户规矩），只学结构与做法：读第三方从发布包里取出的版本，拆出它与我们的差距，用自己的话重写，再拿真模型新旧对比。差距里与使用者报的问题（提取轮数不够、常驻挤满、重复）直接相关的几条：

- 旧写法不提轮数有限，也不教批量；「要改时才看」实际把模型引向看一个、改一个，轮数耗在来回上。
- 模块那一行不写常驻上限，模型写满被拒才知道。
- 没有对每个模块都成立的两条：拿不准是否长期有用就不存、已完成的工作与进度不是记忆；也没要求先在别的层找同一条事实。

## 决定

[`defaultExtractPrompt`](../../../packages/core/src/memory/extract.ts#symbol=defaultExtractPrompt) 改成：

1. **两轮做完**：一轮把可能要改的文件一起看完，一轮把要写的一起写完，然后停；不来回，也不去文件、命令、网页核实事实。保留机制说明：没看过的 indexed 文件改不了，常驻模块因为全文已在指令里所以算看过。
2. **常驻模块带上限**：模块那一行写出 `resident, limit N characters`；放不下就在同一次写里整份重写得更短，**不因为满了就换模块放**。
3. **对每个模块都成立的两条**：拿不准以后还有没有用就不存，已完成的工作、当前任务进度、这次会话发生了什么不是记忆；一条事实只放一个地方——写之前在「Stored now」里找，包括别的层，有了就更新或不动，不在更窄的层重复更宽一层已有的。
4. 其余不变：从哪句看起、上次没看完的提示、选最宽的一层、索引由系统重建、绝对日期、不存凭据、偏好只认用户本人的话、什么都不写是正常结果。

## 数据（DeepSeek `deepseek-flash`，单层、内建三个模块）

场景：常驻 `user` 预置到 1356/1400 字符；notes 已有「测试一律用 bun 跑」等 8 条；对话六句——一句已存过、一句新的个人习惯（得先压常驻才放得下）、一条项目事实（staging 地址与部署前知会运维）、一个提交偏好、一句当前任务进度（不该存）、一条发版规矩。轮数上限 5。

| | 在轮数内跑完 | 平均模型调用 | 被预算拒过 | 写出重复 / 误存任务进度 |
|---|---|---|---|---|
| 旧写法（6 次） | 5/6 | 4.8 | 3/6 | 0 / 0 |
| 新写法（9 次） | 8/9 | 3.8 | 2/9 | 0 / 0 |

新写法最后 6 次全部按「一轮看、一轮写」做完（3 次模型调用）。个人习惯该归哪个模块在内建模块里本就两可（`memory` 模块的说明也收「用户告诉过你他想怎样工作」），两种写法都有放进 notes 的时候，不计入判断。样本小，只说明方向。

## 整理指令为什么这次不换

同一套办法试了整理（层里有两条重复、一条被推翻、一条相对日期、常驻 `user` 1365/1400 且有一处重复）。三种写法都合并了重复、去掉了被推翻的、改掉了相对日期；差别全在**常驻模块被压掉多少事实**与**调用次数**，而这两项在 `deepseek-flash` 上波动很大：

| | 平均模型调用 | 常驻 `user` 保留的事实（18 个关键点） |
|---|---|---|
| 现行写法 | 4.7（4–5） | 11、10、17 |
| 全面重写版 | 12（6、19、11） | 13、18、18 |
| 只改大小那条的折中版 | 9（15、6、6） | 14、18、9 |

现行写法会把一个离上限还有余量的常驻模块压掉约三成事实；全面重写版保住了事实，但有的时候调用次数翻倍以上——使用者报的正是「整理成本高」。两头都不满足，所以缺省先不动，取舍交给用户（见待拍板）。

## 待拍板

- 整理指令：要「少丢事实」还是「少花调用」，或者不靠措辞、加一道机制（例如整理不许把一个没超上限的常驻模块压到原来的某个比例以下）。
- 要不要用更强的模型（如 `deepseek-v4-pro`）再测一轮——`deepseek-flash` 的波动可能放大了差别。
