# 双语文档同步

双语文档的英文 `.md` 与中文 `.zh.md` 必须说同一件事。结构与代码块由 `bun scripts/docs-lint.ts` 机械判定；**意思是否一致**由本 skill 的独立回译核对判定，核对通过即可重录配对记录，不必请用户确认（CLAUDE.md 的双语规则允许这条路）。

本 skill 只判翻译是否等价，不判内容对不对：命令、行为、默认值是否属实，照 CLAUDE.md「Writing documentation from source」去核实。

## 1. 定范围、定源侧

- 双语文档清单以 `docs/docs.manifest.json` 里 `bilingual: true` 的条目为准。
- 对每份改过的文档，看两侧各改了什么（`git diff -- <文档>.md <文档>.zh.md`，已提交的就对基线提交做 diff）。
- **源侧**是这次改动实际写下内容的那一侧；另一侧是**跟随侧**。两侧都有人手写改动、且改的不是同一处时，各自是各自那几处的源。

完成判据：列出每份文档改动的块（段落、列表项、表格行、标题），每块标明源侧。

## 2. 把跟随侧改到位

- 跟随侧在**同一位置**做对应改动：章节、列表、表格、代码块的数量和顺序与源侧一致。
- 代码块（含代码里的注释）从源侧**逐字节复制**，不翻译。
- 术语先在跟随侧文件里找已有译法并沿用，不自造新词；产品名、包名、命令、`runtime` / `provider` / `extension` 这类中文侧已保留英文的词照旧保留。
- 只改源侧改过的块，不顺手润色其他段落——那会扩大核对范围，也会引入未经核对的改动。

完成判据：`bun scripts/docs-lint.ts` 除 pairing 外全绿，pairing 只剩「改过但两侧未重新确认」这一类；出现「结构签名不一致」或缺语言切换行，回到本步修。

## 3. 独立回译核对

改动只在代码块里时跳过本步（代码块逐字节一致已由 code / pairing 门证明），直接到第 5 步。

核对由**两个全新的 subagent** 做，都用 `general-purpose`，**不能用 fork**：fork 继承了本会话的上下文，看过源侧原文，回译会被带偏。回译那个的 prompt 开头必须写明「不要读取、搜索任何文件，也不要运行命令」——否则它能自己去读英文侧，盲译就不盲了。

**3a. 回译**：只给中文，不给英文、不给 diff、不说英文侧怎么写。

> 不要读取、搜索任何文件，也不要运行命令，只根据下面给出的文本工作。
>
> 下面是若干编号的中文文档片段。逐条翻译成英文，要求忠实而不是通顺：保留每个限定词、条件、否定、数字和举例；原文含糊的地方保持含糊，不要替它补全。行内代码、链接、命令原样保留。只输出编号和译文。
>
> （粘贴本次改动涉及的中文块，编号 1..N；新增块和改动块都要，删掉的块不用）

**3b. 比对**：给英文原块、回译、中文块，以及两侧文件的完整 diff。

> 你在核对一份双语文档的一次改动。下面给出：① 英文侧的块（编号 1..N）；② 同编号中文块；③ 另一个人**没看过英文**、只从中文回译出的英文；④ 两侧文件本次的完整 diff。
>
> 逐编号比较 ① 与 ③ 的**意思**，措辞不同不算出入。只报这些：事实或数字不同；条件、范围、限定词（only / at least / 默认 / 可选）不同；否定或因果关系反了；一侧有而另一侧没有的信息、步骤或警告；命令、包名、链接指向不同。再用 ④ 检查：两侧 diff 里每一行改动的正文是否都落在 1..N 里，没覆盖到的列为「未覆盖」。
>
> 输出：每个编号一行 `N: 一致` 或 `N: 出入——<一句话说清哪里不同，哪侧更可能是对的>`；最后列「未覆盖」的行，没有就写「未覆盖：无」。

完成判据：拿到比对结果，每个编号都有结论，并有「未覆盖」一行。

## 4. 处理出入

- **出入**：改错的那一侧。通常是跟随侧译得不准；如果问题出在源侧本身有歧义，先把源侧写清楚，再同步跟随侧。
- **未覆盖**：把漏掉的块补进编号，一起重核。
- 改完后对**改动过的块**重新做第 3 步，每轮都用全新的 subagent，不复用上一轮的。
- 连续两轮仍有出入，或者出入其实是「这段该写什么」的内容分歧而非翻译问题，停下来，把分歧摆给用户拍板。

完成判据：最近一轮所有编号都是「一致」，且「未覆盖：无」。

## 5. 重录配对、跑门

```bash
bun scripts/docs-lint.ts --write-pairing README.md   # 点名这次核对通过的文档，多份就依次列出
bun scripts/docs-lint.ts
bun test test/docs.test.ts
```

- 只点名第 4 步核对通过的文档；不要顺手重录没核对过的。
- 判绿看真实退出码。

完成判据：两条检查退出码都是 0。

## 6. 留痕

提交由外层任务决定何时做；做的时候，在提交信息正文里写一行核对结论，例如：

```text
双语核对：README 4 个块，独立回译比对 0 处出入（第 1 轮）
```

有过出入就写清修了哪几处、第几轮通过。配对记录只存哈希，这一行是「谁、怎么确认的」唯一的记录。向用户汇报时同样带上这一行。
